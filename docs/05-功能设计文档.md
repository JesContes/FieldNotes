## 1. 概述

### 1.1 背景与目标

出行前最怕“到了地方才发现少带东西”。市面上的清单 App 往往把物品、模板、行程拆成互不相通的功能，或强制登录 / 同步。「寸笺」把四件事放在同一个本地数据模型里：

1. **物品库**：所有可能带出门的东西，按分类管理；
2. **清单模板**：把“夏季游”“短途出差”这类固定组合存下来；
3. **出行计划**：一次具体的旅行，含目的地、时间与清单；
4. **勾选与红点**：边打包边勾，没勾完的计划一直提醒。

设计原则：**录入轻、勾选快、历史稳、迁移全**。

### 1.2 范围

**包含（v1.0）**

- 物品 / 分类 / 模板 / 计划四类数据的增删改查；
- 计划直接添加物品、从模板批量导入；
- 模板从其他模板 / 历史计划导入，条目移除；
- 清单勾选 / 取消，勾选项中划线 + 灰色；
- 未勾选计划红点提示；
- 全量导出 / 导入（JSON / gzip，合并 / 覆盖）；
- 纯本地存储与离线可用。

**不包含（v1.0）**

- 登录、账号、云同步、多人协作；
- 网络请求、在线模板市场；
- 出行提醒 / 通知、桌面小组件（列入 P2）；
- 物品数量、重量、行李额计算（列入 P2）；
- 图片、附件、语音录入；
- 深色主题（P2）。

### 1.3 名词定义

| 名词 | 定义 |
| --- | --- |
| 物品（Item） | 物品库中的一条记录：名称 + 分类 + 可选备注；名称全局唯一 |
| 分类（Category） | 物品的归类，含名称与颜色；6 个预置分类，可增删改 |
| 未分类 | 虚拟分类，表示 `categoryId = null`；不是数据库记录，不可改名 / 删除 |
| 模板（Template） | 一组可复用的物品条目，含名称、说明、主题色 |
| 模板条目（TemplateItem） | 模板中的一行：物品名 + 分类名快照 + 排序 |
| 计划（Plan） | 一次具体出行：目的地、可选名称、起止日期、备注、主题色 |
| 清单条目（PlanItem） | 计划中的一行：物品名 + 分类名快照 + 勾选态 + 排序 |
| 勾选（checked） | 清单条目是否已打包；勾选后名称中划线并变灰 |
| 红点（hasUnchecked） | 计划存在未勾选条目的视觉提示 |
| nameKey | 名称归一化键：去首尾空白、合并连续空白、转小写，用于唯一与去重 |
| 快照 | 条目保存物品名与分类名的副本，不随物品库后续修改而变化 |

## 3. 数据模型

### 3.1 实体关系

```
┌──────────────┐         ┌──────────────┐
│   Category   │ 1     n │     Item     │
│  分类         ├─────────┤    物品       │
└──────────────┘         └──────┬───────┘
                                │ 来源提示（可空，无外键）
                                │
┌──────────────┐         ┌──────▼──────────┐
│   Template   │ 1     n │  TemplateItem   │
│   模板        ├─────────┤  模板条目（快照） │
└──────────────┘         └─────────────────┘

┌──────────────┐         ┌─────────────────┐
│     Plan     │ 1     n │     PlanItem    │
│   出行计划    ├─────────┤  清单条目（快照） │
└──────────────┘         └─────────────────┘
```

- 模板条目 / 清单条目**不持有分类外键**，只保存 `categoryName` 快照；
- 模板条目 / 清单条目可选保存 `sourceItemId`，仅作来源提示，**不建外键**，物品删除后仍保留；
- 删除计划 / 模板级联删除其条目；删除分类把物品的 `categoryId` 置空。

### 3.2 Category（分类）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | Long | PK，自增 | — |
| name | String | 非空，1–12 字 | 展示名，如「日用品」 |
| nameKey | String | 非空，唯一 | 归一化键，用于重名判断 |
| colorHex | String | 非空，`#RRGGBB` | 分类色点 |
| sortOrder | Int | 默认 0 | 预置顺序 / P1 手动排序 |
| createdAt | Long | 非空 | Unix 秒 |

预置 6 个分类（首次启动幂等写入）：

| 名称 | 颜色 |
| --- | --- |
| 日用品 | `#66CCFF` |
| 服装 | `#4DB6AC` |
| 电子设备 | `#81C784` |
| 证件 | `#FFD54F` |
| 药品 | `#FFB74D` |
| 其他 | `#F06292` |

> 「未分类」不入库；查询时用 `LEFT JOIN` 或映射为虚拟行，颜色 `#E8EEF3`，不可编辑 / 删除。

### 3.8 建表 SQL（示意）

```sql
CREATE TABLE category (
    id         INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
    name       TEXT    NOT NULL,
    name_key   TEXT    NOT NULL,
    color_hex  TEXT    NOT NULL,
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_at INTEGER NOT NULL
);
CREATE UNIQUE INDEX idx_category_name_key ON category(name_key);

CREATE TABLE item (
    id          INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
    name        TEXT    NOT NULL,
    name_key    TEXT    NOT NULL,
    category_id INTEGER REFERENCES category(id) ON DELETE SET NULL,
    note        TEXT    NOT NULL DEFAULT '',
    created_at  INTEGER NOT NULL,
    updated_at  INTEGER NOT NULL
);
CREATE UNIQUE INDEX idx_item_name_key ON item(name_key);
CREATE INDEX idx_item_category ON item(category_id);

CREATE TABLE template (
    id           INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
    name         TEXT    NOT NULL,
    name_key     TEXT    NOT NULL,
    description  TEXT    NOT NULL DEFAULT '',
    color_hex    TEXT    NOT NULL,
    created_at   INTEGER NOT NULL,
    updated_at   INTEGER NOT NULL,
    last_used_at INTEGER
);
CREATE UNIQUE INDEX idx_template_name_key ON template(name_key);

CREATE TABLE template_item (
    id             INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
    template_id    INTEGER NOT NULL REFERENCES template(id) ON DELETE CASCADE,
    name           TEXT    NOT NULL,
    name_key       TEXT    NOT NULL,
    category_name  TEXT    NOT NULL DEFAULT '',
    sort_order     INTEGER NOT NULL DEFAULT 0,
    source_item_id INTEGER
);
CREATE UNIQUE INDEX idx_template_item_unique ON template_item(template_id, name_key);

CREATE TABLE plan (
    id               INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
    title            TEXT    NOT NULL DEFAULT '',
    destination      TEXT    NOT NULL,
    start_epoch_day  INTEGER NOT NULL,
    end_epoch_day    INTEGER NOT NULL,
    note             TEXT    NOT NULL DEFAULT '',
    color_hex        TEXT    NOT NULL,
    created_at       INTEGER NOT NULL,
    updated_at       INTEGER NOT NULL
);
CREATE INDEX idx_plan_start ON plan(start_epoch_day);

CREATE TABLE plan_item (
    id             INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
    plan_id        INTEGER NOT NULL REFERENCES plan(id) ON DELETE CASCADE,
    name           TEXT    NOT NULL,
    name_key       TEXT    NOT NULL,
    category_name  TEXT    NOT NULL DEFAULT '',
    checked        INTEGER NOT NULL DEFAULT 0,
    sort_order     INTEGER NOT NULL DEFAULT 0,
    source_item_id INTEGER
);
CREATE UNIQUE INDEX idx_plan_item_unique ON plan_item(plan_id, name_key);
CREATE INDEX idx_plan_item_plan ON plan_item(plan_id);
```

> Room 实体使用驼峰字段 + `@ColumnInfo(name = "name_key")` 映射；`checked` 为 Boolean，SQLite 存 0/1。外键在 `@Entity(foreignKeys = ...)` 中声明，Room 自动开启 `PRAGMA foreign_keys = ON`。

## 4. 界面与交互设计

> 视觉细节见《01 · 界面原型图》；本节定义结构与行为。

### 4.1 出行（计划列表）

| 区域 | 内容 | 行为 |
| --- | --- | --- |
| 标题栏 | 「寸笺」+ 副标题 + 搜索 | 搜索按目的地 / 名称过滤，输入即生效 |
| 概览 | 全部计划 / 待收 N 件 / 共 N 个计划 | 只读 |
| 筛选 | 全部 / 进行中 / 未开始 / 已结束 | 单选；记忆到 DataStore |
| 卡片 | 色块、目的地、计划名、状态、日期、进度、预览、红点 | 单击进详情；长按无操作（避免与滚动冲突） |
| FAB | ＋ | 新建计划 |
| 空状态 | 插画 + 文案 + 新建按钮 | — |

筛选后的空结果：若筛选条件非「全部」且确实无匹配，显示“没有进行中的计划”，并提供“查看全部”按钮。

### 4.2 计划详情

| 区域 | 内容 | 行为 |
| --- | --- | --- |
| 顶栏 | 返回 + 标题 + 更多 | 更多：存为模板 / 全部勾选 / 全部取消 / 编辑 / 删除 |
| Hero | 目的地、日期、状态、主题色 | 只读 |
| 进度 | `已收 x/y`、`未收 N`、进度条、全部勾选 | 全部勾选 = 批量 `checked = true` |
| 清单 | 按分类分组，组头计数 | 点击行切换勾选；左滑移除 + 撤销 |
| 底部 | 导入模板 / 添加物品 | 打开对应弹层 |
| 空清单 | “清单还是空的” | 两个入口 |
| 删除计划 | 对话框 | 说明将删除 N 条清单记录 |

## 5. 核心业务规则

### 5.1 名称归一化与唯一性

```kotlin
fun normalizeName(raw: String): String =
    raw.trim().replace(Regex("\\s+"), " ")

fun nameKey(raw: String): String =
    normalizeName(raw).lowercase(Locale.ROOT)
```

- 中文不受 `lowercase` 影响；拉丁字母大小写不敏感；
- 名称长度按 **Unicode 码点** 计数（emoji 算 1 个），而非 UTF-16 `length`；
- 物品名全局唯一；模板名全局唯一；分类名全局唯一；计划名不要求唯一（同一目的地可多次出行）；
- 模板 / 计划内条目按 `nameKey` 去重，不同模板 / 计划之间互不影响。

### 5.2 快照规则

- 添加物品到计划 / 模板时，复制 `item.name` 与 `item.category?.name ?: ""`；
- 之后物品改名、换分类、删除，**不修改**已有条目；
- 分类改名不回溯历史条目的 `categoryName`；
- 模板导入到计划时，再次复制模板条目的名称与分类，不引用模板条目 id；
- 这样保证历史计划稳定，也避免外键级联带来的“删除物品导致清单缺行”。

### 5.3 计划状态

设 `today = LocalDate.now()`，`start` / `end` 为计划起止日：

| 条件 | 状态 | 文案 | 颜色 |
| --- | --- | --- | --- |
| `today < start` | UPCOMING | `还有 N 天出发`，N = start − today | 浅蓝底 / `primaryInk` |
| `start ≤ today ≤ end` | ONGOING | `进行中 · 第 N 天`，N = today − start + 1 | 绿底 / 绿字 |
| `today > end` | PAST | `已结束 N 天`，N = today − end | 灰底 / 灰字 |

- 状态不落库，每次回前台 / 重新订阅时按当天重算；
- 跨天驻留：`MainActivity.onResume` 比较缓存日期，变化则触发重算；
- 当天出发且当天返回：`进行中 · 第 1 天`；
- 时区：全部用设备本地时区的 `LocalDate`，不存 UTC 时刻。

### 5.4 红点

```kotlin
val hasUnchecked = total > 0 && checked < total
```

- 计划列表卡片：目的地右侧 8dp 红点；
- 详情页：用「未收 N 件」红色胶囊，不重复红点；
- 进行中 / 未开始 / 已结束计划都遵守同一规则（需求未限定状态）；
- 空清单不显示红点；
- 红点不是唯一提示：卡片有 `x/y 已收`，详情有 `未收 N 件`，无障碍读屏播报数量。

### 5.5 进度

```
progress = if (total == 0) 0f else checked.toFloat() / total
percent  = (progress * 100).roundToInt()
```

- `total` = 清单条目数（含已勾选）；
- 添加 / 导入模板后分母增大，进度可能下降，属预期；
- 移除条目后分母减小；
- 进度条颜色固定主色；100% 时可变为绿色 `#2E9E6B`（P1）。

### 5.6 勾选视觉

| 状态 | 复选框 | 名称 |
| --- | --- | --- |
| 未勾选 | 20dp 空心圆，描边 `#C9D6E0` 1.5dp | `ink #22313F`，Medium |
| 勾选 | 20dp 主色实心 + 白色对勾 | `#9AB0C0` + `TextDecoration.LineThrough` |
| 按下 | 行底色 `#F2FAFF` | 不变 |

- 中划线与灰色**同时**出现，缺一不可；
- 勾选不做位移动画，仅颜色 / 删除线 120ms 过渡；
- 复选框 `role = Checkbox`，读屏播报“已勾选 / 未勾选”。

### 5.7 排序

| 列表 | 规则 |
| --- | --- |
| 计划 | 进行中 → 未开始（start 升序）→ 已结束（end 降序）；同组内 `updatedAt` 降序兜底 |
| 模板 | `lastUsedAt` 降序（null 最后）→ `updatedAt` 降序 |
| 物品 | 分类 `sortOrder` → 物品名 `Collator.getInstance(Locale.CHINA)` |
| 计划内分组 | 分类 `sortOrder`；未知分类按名称；未分类最后 |
| 组内条目 | `sortOrder` 升序；相同则 id 升序 |

### 5.8 添加物品到计划

- 输入：`planId` + 选中的 `itemId` 列表；
- 事务内逐条插入 `PlanItemEntity`：
  - `name = item.name`、`categoryName = item.category?.name ?: ""`；
  - `checked = false`；
  - `sortOrder = maxSortOrder + 1 + index`；
  - `sourceItemId = item.id`；
- 唯一索引 `(planId, nameKey)` 兜底，冲突跳过；
- 返回插入数 / 跳过数，Toast 汇总。

### 5.9 导入模板到计划

- 读取模板条目（按 `sortOrder`）；
- 预计算计划内已有 `nameKey` 集合；
- 过滤重复，保持模板顺序；
- 事务内批量插入，追加到现有 `maxSortOrder` 之后；
- 更新模板 `lastUsedAt = now`（即使全部重复，也表示用户尝试使用过）；
- 返回 `added` / `skipped`，用于按钮文案与 Toast。

### 5.10 模板从模板 / 计划导入

| 来源 | 复制内容 | 勾选态 | 去重 |
| --- | --- | --- | --- |
| 另一个模板 | 全部模板条目 | 无 | 按目标模板 `nameKey` |
| 历史计划 | 全部清单条目 | **不带入**，一律未勾选 | 按目标模板 `nameKey` |

- 复制后追加到目标模板末尾；
- 来源条目的分类名快照原样保留；
- 若来源为空：Toast“来源没有可导入的物品”。

### 5.11 计划存为模板

- 输入模板名（默认 `计划名 + " 模板"`）；
- 复制计划全部清单条目为模板条目，**不带勾选态**；
- 事务内插入 `template` + `template_item`；
- 成功后跳转模板详情，Toast「已存为模板」；
- 名称重复：提示改名，不覆盖已有模板。

### 5.12 删除分类

```
删除分类(id):
    count = 该分类下物品数
    用户确认("该分类下有 N 件物品，删除后归入未分类")
    事务:
        UPDATE item SET category_id = NULL WHERE category_id = :id
        DELETE FROM category WHERE id = :id
    Flow 刷新
```

- 计划 / 模板中的 `categoryName` 快照不变；
- 若当前物品筛选正是该分类，回退「全部」；
- 「未分类」行不可删除。

### 5.13 删除物品

- 仅删除 `item` 行；
- `plan_item` / `template_item` 保留名称与分类快照；
- 提示文案明确：“已创建的计划与模板中的同名物品会保留”；
- 若物品在多个模板中，不影响模板。

### 5.14 日期与时长

- 出发日、返程日均为 `LocalDate`，存 `epochDay`；
- `end >= start`；同一天允许；
- 天数 = `ChronoUnit.DAYS.between(start, end) + 1`；
- 展示格式：`2026.10.26 – 10.30 · 5 天`（跨年时显示完整年份）；
- 不限制过去 / 未来范围，但导入时校验 1900–2200，防脏数据。

### 5.15 模板 `lastUsedAt`

- 导入模板到计划成功时更新；
- 计划存为模板不更新（新建模板 `lastUsedAt = null`）；
- 复制模板不继承 `lastUsedAt`（新模板未使用过）；
- 模板列表按它排序，null 置后。

### 5.16 数据统计

- 计划数 = `COUNT(plan)`；
- 模板数 = `COUNT(template)`；
- 物品数 = `COUNT(item)`；
- 分类数 = `COUNT(category)`（不含虚拟「未分类」）；
- 待收件数 = 所有计划 `COUNT(plan_item WHERE checked = 0)`；
- 这些数字由 Flow 派生，任何写入后自动更新。

// Repository
suspend fun addItemsToPlan(planId: Long, itemIds: List<Long>): AddResult =
    db.withTransaction {
        val plan = planDao.getPlan(planId) ?: error("计划不存在")
        val items = itemDao.getByIdsWithCategory(itemIds)   // 投影带分类名
        val existing = planDao.getPlanItems(planId).map { it.nameKey }.toSet()
        var order = (planDao.maxSortOrder(planId) ?: 0)
        val toInsert = mutableListOf<PlanItemEntity>()
        var skipped = 0
        for (item in items) {
            if (item.nameKey in existing) { skipped++; continue }
            toInsert += PlanItemEntity(
                planId = planId,
                name = item.name,
                nameKey = item.nameKey,
                categoryName = item.categoryName ?: "",
                checked = false,
                sortOrder = ++order,
                sourceItemId = item.id,
            )
        }
        if (toInsert.isNotEmpty()) planDao.insertPlanItems(toInsert)
        AddResult(added = toInsert.size, skipped = skipped)
    }

| 场景 | 处理 |
| --- | --- |
| 物品名为空 / 超 40 字 | 行内错误，保存按钮不提交 |
| 物品重名 | 提示“已存在同名物品”，可跳转编辑 |
| 分类名为空 / 超 12 字 | 行内错误 |
| 分类重名 | 提示“已存在同名分类” |
| 删除分类下有物品 | 二次确认，文案含件数；确认后归入未分类 |
| 删除物品 | 二次确认；说明历史计划 / 模板保留快照 |
| 模板重名 | 提示改名，不覆盖 |
| 模板条目为空 | 导入按钮禁用；Toast“模板没有物品” |
| 添加物品全部重复 | 不写库，Toast“所选物品均在清单中” |
| 导入模板全部重复 | 不写库，Toast“该模板物品均已在清单中” |
| 计划目的地为空 | 行内错误，不写库 |
| 返程早于出发 | 控件阻止 + 保存校验兜底 |
| 备注超 200 字 | 输入框限制，保存校验兜底 |
| 删除计划时已不存在 | 影响行数 0，Toast 并返回列表 |
| 勾选时条目已被移除 | 影响行数 0，Flow 刷新，不报错 |
| 计划清单为空 | 空状态，不显示红点，进度 0/0 |
| 历史计划条目分类已删除 | 快照分类名照常展示；分组排在已知分类后 |
| 模板 / 计划条目名与物品库不同 | 允许，快照独立；不做自动同步 |
| 跨天 | 回前台重算状态；红点不受影响 |
| 系统时间被修改 | 每次回前台按系统日期重算，天然容错 |
| 导入文件格式不符 | “这不是有效的寸笺导出文件”，不写库 |
| 导入版本过高 | “文件版本过高，请先升级应用” |
| 导入文件 > 32 MB | 拒绝并提示 |
| 导入部分脏数据 | 跳过并计数，最后汇总“忽略 N 条无效数据” |
| 导入过程中异常 | 事务回滚，Toast“导入失败，请重试” |
| 导出时存储空间不足 | 捕获 IO 异常，Toast“导出失败，请检查存储空间” |
| 用户取消 SAF | 静默返回，不提示错误 |
| 数据库升级失败 | 保留旧库，提示重启；禁止 destructive migration |

## 8. 状态与事件管理

- **状态**：每个页面一个 `StateFlow<UiState>`，`stateIn(WhileSubscribed(5_000))`；
- **一次性事件**：`Channel<UiEvent>(BUFFERED)`，UI 侧 `LaunchedEffect` 消费；包括 Toast、导航、关闭弹层、Snackbar；
- **弹层开关**：属于 UI 状态时放在 `remember`；属于业务状态（如导入预览）放在 UiState；
- **配置变更**：ViewModel 存活；筛选项存 DataStore；滚动位置由 `rememberLazyListState` + `rememberSaveable` 保留；
- **进程死亡恢复**：导航栈由 Navigation 恢复；未保存表单不保证恢复（v1 接受）。

## 9. 非功能需求

| 类别 | 指标 |
| --- | --- |
| 性能 | 1000 物品 / 100 计划 / 5000 条目下，列表滚动 60fps；勾选响应 < 100ms |
| 启动 | 冷启动 < 1.5s（中端机）；首屏不等导入导出 |
| 存储 | 1000 物品 + 100 计划约 < 5 MB（含索引） |
| 包体积 | release APK < 15 MB（无图片 / 无重型依赖） |
| 离线 | 100% 可用，无网络权限 |
| 隐私 | 数据仅存应用私有目录；`allowBackup=false`；无统计 / 崩溃上报 SDK |
| 稳定性 | 数据库操作挂起 + try-catch；目标崩溃率 < 0.1% |
| 可访问性 | 48dp 触摸目标；字体 200%；红点有文字替代；正文对比度 ≥ 4.5:1，品牌色填充上的文字经对比度检查后定稿 |
| 兼容 | API 26–36；手机 / 折叠屏 / 平板 |
