## 3. 端到端验收脚本（换机往返）

**准备**：设备 A 全新安装。

1. 确认预置 6 分类；
2. 新增物品：牙刷、牙膏、防晒霜、短袖、短裤、薄外套、充电器、相机、护照、身份证（10 件）；
3. 新建模板「夏季游」：加入短袖、短裤、防晒霜、驱蚊水、洗漱包、充电器、相机、护照（8 件）；
4. 再建模板「短途出差」：加入短袖、充电器、充电宝、身份证（4 件）；
5. 新建计划「东京五日游」：东京，2026-10-26 至 10-30；
6. 直接添加：护照、充电器、短袖；
7. 导入模板「夏季游」→ 应有 5 件新增、3 件跳过（护照 / 充电器 / 短袖）；
8. 勾选护照、短袖 → 计划 2/8，红点仍在；
9. 把计划存为模板「东京清单」；
10. 模板「东京清单」→ 从计划导入「东京五日游」→ 全部跳过；
11. 移除模板「东京清单」中的“相机” → 撤销；
12. 我的 → 导出 JSON，记录体积；
13. 卸载重装 → 我的 → 导入 JSON → 合并；
14. 核对：3 个模板、1 个计划、10 件物品、6 个分类；计划 2/8 勾选；红点存在；
15. 再导出 gzip → 清空数据 → 导入 gzip → 覆盖；
16. 核对与步骤 14 完全一致；
17. 重复导入 → 合并 → 全部跳过，数量不变。

**通过标准**：以上 17 步无崩溃、无重复、无丢失、无引用错位；勾选态、红点、模板 `lastUsedAt` 均正确。

## 5. 边界与异常清单

| 场景 | 期望 |
| --- | --- |
| 0 个计划 / 模板 / 物品 | 各自空状态；统计为 0；无崩溃 |
| 计划清单 100+ 条 | 滚动流畅；勾选只更新单行；分组计数正确 |
| 物品 1000 件 | 搜索 < 200ms；列表按需组合 |
| 名称含 emoji / 全角空格 | 归一化正确；长度按码点；导出正常 |
| 名称仅空白 | 校验失败，不写库 |
| 分类全删光 | 物品全部未分类；分类管理只剩「未分类」；可再建 |
| 计划跨年 | 日期显示完整年份；天数正确 |
| 计划过去 5 年 | 显示“已结束 1825 天”；红点规则不变 |
| 系统日期跨天 | 回前台状态更新；无需重启 |
| 模板条目名与物品库不同 | 允许；快照独立 |
| 删除物品后导入旧模板 | 正常导入同名快照；不要求物品存在 |
| 导入文件只有分类 | 其他数组为空；导入成功 |
| 导入空数组文件 | 提示“文件不包含任何数据”；不写库 |
| 覆盖时文件损坏 | 校验在清空前完成；原数据不动 |
| 导入时空间不足 | 事务回滚；Toast 提示 |
| 数据库升级 | 保留数据；禁止 destructive migration |
