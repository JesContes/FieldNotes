# 寸笺 · 技术选型文档

| 项目 | 内容 |
| --- | --- |
| 应用名称 | 寸笺（Field Notes） |
| 平台 | Android（手机 / 折叠屏 / 平板） |
| 包名 | `com.fieldnotes` |
| 文档版本 | v1.0 |
| 数据形态 | 纯本地存储，无登录、无网络权限、无云同步 |
| 选型基准 | `D:\projects\EndFieldTime`（已编译、已实机验证的同架构项目） |

---

## 1. 项目概述与约束

「寸笺」管理四类本地数据：**物品**、**物品分类**、**清单模板**、**出行计划**。核心交互是“建计划 → 加物品 / 导模板 → 逐项勾选”。技术选型受以下约束：

1. **纯本地**：数据不出设备，不申请 `INTERNET`，不做账号与云同步；
2. **离线可靠**：数据库事务 + 导入导出，断电 / 杀进程不丢数据；
3. **轻量**：单 `app` module，功能聚焦，不引入 IM、图片加载、统计 SDK；
4. **半平面风 UI**：大圆角、纯色块、轻投影、自定义复选框与分组卡片，要求 UI 框架对自定义样式友好；
5. **可演进**：未来可能加桌面小组件、深色主题、提醒、云备份，架构需留扩展点；
6. **与参考项目一致**：沿用其已验证的 Compose + Room + Flow + 手动 DI 组合，降低实施风险。

## 2. 技术栈总览

| 分层 | 选型 | 版本 | 说明 |
| --- | --- | --- | --- |
| 语言 | Kotlin | 2.3.21（AGP 内置） | 协程、Flow、数据类、空安全 |
| UI | Jetpack Compose + Material 3 | BOM 2025.12.01 | 声明式 UI；复选框、分组卡、弹层实现成本低 |
| 架构 | MVVM + 单向数据流（UDF） | — | UI 只渲染 StateFlow，事件上行 |
| 导航 | Navigation Compose | 2.9.3 | 单 Activity，四页签 + 详情路由 |
| 主存储 | Room（SQLite）+ KSP | 2.8.2 | 六张表、外键级联、Flow 响应式查询 |
| 偏好 | DataStore Preferences | 1.1.7 | 记住筛选状态、上次导入方式 |
| 异步 | Coroutines + Flow | 随 Kotlin | 挂起函数 + `stateIn` 驱动 UI |
| 依赖注入 | 手动 DI（`AppContainer`） | — | 依赖只有 DB / DAO / Repo / Store，Hilt 过重 |
| 日期 | `java.time.LocalDate` | minSdk 26 原生 | epochDay 存储、区间天数计算 |
| 导入导出 | `org.json` + `java.util.zip.GZIP*` + SAF | — | 零第三方依赖、格式可控、可人工排查 |

## 3. 关键选型与理由

### 3.1 UI：Jetpack Compose + Material 3

| 对比项 | Compose + M3 | 传统 View / XML |
| --- | --- | --- |
| 勾选行状态 | `TextDecoration.LineThrough` + `animateColor` 一行完成 | 手动改 TextView paintFlags + 颜色 |
| 分组清单 | `LazyColumn` + `stickyHeader` / 分组数据 | 多级 Adapter 或 RecyclerView 嵌套 |
| 自定义复选框 | `Canvas` / `Icon` 组合，完全可控 | 自定义 Drawable + selector |
| 底部弹层 | `ModalBottomSheet` 官方组件 | BottomSheetDialog + 布局 |
| 状态驱动 | `StateFlow` → `collectAsStateWithLifecycle()` | 手动 `notifyDataSetChanged()` |
| 主题令牌 | `ColorScheme` + `Shapes` + `Typography` 集中管理 | themes.xml + styles.xml 分散 |

**结论：Compose + M3。** 本项目视觉高度定制（复选框、进度条、红点、分组卡、半平面投影），Compose 的自定义成本明显低于 View 体系；且与参考项目保持同一套 UI 经验。

M3 组件映射：

| 场景 | 组件 |
| --- | --- |
| 底部四页签 | `NavigationBar` + `NavigationBarItem` |
| 计划 / 模板 / 物品列表 | `LazyColumn` + `Card` / 自绘 `Surface` |
| 状态筛选 | `FilterChip`（单选） |
| 添加物品 / 导入模板 / 编辑物品 | `ModalBottomSheet` |
| 日期区间 | `DateRangePicker` + `DatePickerDialog` |
| 删除 / 导入确认 | `AlertDialog`（自定义内容布局） |
| 轻提示 / 撤销 | `SnackbarHost` + `SnackbarResult` |
| 空状态 | 自绘 `EmptyState`（图标 + 文案 + 按钮） |

**窗口与系统栏**：Android 15（API 35+）默认强制 edge-to-edge。`MainActivity` 调用 `enableEdgeToEdge()`，页面根节点用 `Scaffold` 的 `contentWindowInsets = WindowInsets.safeDrawing` 处理状态栏 / 导航栏；弹层用 `Modifier.imePadding()` 避让键盘；底部操作栏使用 `WindowInsets.navigationBars` 额外内边距，避免被手势条遮挡。

**响应式**：使用 `androidx.compose.material3:material3-window-size-class` 的 `calculateWindowSizeClass()`，在 600dp / 840dp 断点切换单列、双列与列表-详情双栏（详见《01 · 界面原型图》§7.1）。

### 3.2 架构：MVVM + 单向数据流

```
┌─────────────────────────────────────────────────────────────┐
│ UI（Compose）                                                │
│   PlanListScreen / PlanDetailScreen / TemplateScreen ...     │
│   事件 ↑ onToggle / onAddItems / onImportTemplate / onExport │
│   状态 ↓ StateFlow<UiState>（collectAsStateWithLifecycle）    │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│ ViewModel（每个页面一个）                                     │
│   组装 UiState：状态、进度、红点、分组、排序、筛选             │
│   校验输入、发起事务、发送一次性事件（Channel / SharedFlow）    │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│ Repository（唯一数据源）                                      │
│   计划 / 模板 / 物品 / 分类的读写与事务                        │
│   快照复制、去重、批量导入、lastUsedAt 更新                    │
└───────────┬──────────────────────────────┬──────────────────┘
            │                              │
┌───────────▼───────────┐      ┌───────────▼──────────────────┐
│ Room DAO + SQLite     │      │ DataStore Preferences        │
│ 六张表 / 外键 / Flow   │      │ 筛选记忆 / 导入方式 / 引导标记 │
└───────────────────────┘      └──────────────────────────────┘
```

**单向数据流规则**：

- UI 不直接改列表，所有增删改落库，由 Room 的 `Flow` 自动发射最新数据；
- ViewModel 只做“查询 + 映射 + 校验”，不持有可变集合；
- 一次性事件（Toast、导航、关闭弹层）用 `Channel<UiEvent>`，避免重组后重复消费；
- 配置变更（旋转、折叠）由 ViewModel 存活保证状态不丢。

### 3.3 主存储：Room

| 对比项 | Room | SQLiteOpenHelper | DataStore | Realm |
| --- | --- | --- | --- | --- |
| 多表关联 / 外键 | ✅ 注解 + 级联 | 手写 SQL | ❌ 仅 KV | ✅ |
| 事务 | ✅ `@Transaction` | 手动 BEGIN/COMMIT | ❌ | ✅ |
| 编译期 SQL 校验 | ✅ | ❌ | — | ❌ |
| Flow 响应式查询 | ✅ 原生 | 自己封装 | ✅ | ✅ |
| 迁移 | ✅ `Migration` + schema | 手写 | — | 复杂 |
| 维护方 | Google Jetpack | 平台 | Google Jetpack | MongoDB（第三方） |

**结论：Room。** 六张表存在明确的一对多与级联关系（计划→清单条目、模板→模板条目），且列表必须随勾选即时刷新，Room 的 `@Relation` + `Flow` 正好匹配。

**外键策略**：

- `plan_item.planId` → `plan.id`：`ON DELETE CASCADE`；
- `template_item.templateId` → `template.id`：`ON DELETE CASCADE`；
- `item.categoryId` → `category.id`：`ON DELETE SET NULL`（删除分类后物品归入未分类）；
- 计划 / 模板条目保存**名称与分类名快照**，不引用 `item.id` 作为展示来源；因此删除物品不影响历史清单。

### 3.4 偏好：DataStore Preferences

只保存轻量、非关键数据：

| Key | 类型 | 用途 |
| --- | --- | --- |
| `plan_filter` | String | 计划列表上次筛选（全部 / 进行中 / 未开始 / 已结束） |
| `item_filter` | String | 物品库上次分类筛选 |
| `last_export_gzip` | Boolean | 上次导出是否压缩 |
| `seed_done` | Boolean | 是否已写入预置分类（幂等标记） |

相比 SharedPreferences：Flow 读取、协程安全、无主线程 IO 风险。

### 3.5 依赖注入：手动 DI

依赖图很小：

```
AppContainer
├── FieldNotesDatabase
│   ├── CategoryDao
│   ├── ItemDao
│   ├── TemplateDao
│   ├── PlanDao
│   └── TransferDao（跨表快照 / 清空）
├── SettingsStore(DataStore)
├── FieldNotesRepository(...)
└── ExportCodec / TransferFiles
```

通过 `Application` 持有 `AppContainer`，ViewModel 用 `viewModelFactory { initializer { ... } }` 构造。**不引入 Hilt**：省去 KSP 处理、注解开销与学习成本；参考项目同样采用手动 DI，已验证足够。

### 3.6 导入导出：`org.json` + SAF

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| `org.json`（选中） | 零依赖、键名完全可控、紧凑格式易实现 | 手写解析样板代码 | ✅ |
| kotlinx.serialization | 类型安全、DTO 清晰 | 增加插件与依赖；紧凑键需大量 `@SerialName` | 备选 |
| Gson / Moshi | 成熟 | 反射 / 额外依赖，包体积增加 | ❌ |
| CSV | 可读 | 嵌套模板 / 计划需要多文件或转义，易出半行脏数据 | ❌ |
| 二进制 protobuf | 最小 | 需要 schema，无法人工排查，过度设计 | ❌ |

**结论：紧凑 JSON + 可选 gzip + 系统文件选择器（SAF）。** 不申请存储权限；导入端按文件头 `1F 8B` 识别 gzip，不依赖扩展名。

### 3.7 日期与时间

- 计划日期存 `Long epochDay`（`LocalDate.toEpochDay()`），无时区歧义；
- 计划状态（未开始 / 进行中 / 已结束）用 `LocalDate.now()` 与起止日比较；
- 时间戳（创建 / 更新 / 最后使用）存 Unix **秒**，导出更省字节；展示时转本地时区；
- 跨天刷新：应用回到前台时重算状态；如前台驻留跨过 00:00，可选注册次日 00:00 的一次性任务（P2）。

## 7. 风险与备选

| 风险 | 影响 | 缓解 / 备选 |
| --- | --- | --- |
| Compose 重组导致勾选卡顿 | 长清单掉帧 | 稳定 key + `derivedStateOf`；勾选只更新单行 |
| 大清单首屏慢 | 计划 100+ 条目 | 分组数据在 Repository 一次查完；`LazyColumn` 按需组合 |
| 导入大文件 OOM | 100 MB JSON | 文件上限 32 MB；流式读取 + 逐条校验（P1） |
| 快照与物品库不一致 | 用户困惑 | 文档明确“历史不回溯”；模板/计划条目展示快照 |
| 分类删除误操作 | 物品归入未分类 | 二次确认 + 明确文案 + 可重新归类 |
| 日区间跨时区 | 状态差一天 | 全部用 `LocalDate` + epochDay，不存 UTC 时刻 |
| Hilt 缺席导致 ViewModel 构造冗长 | 样板代码 | Factory 集中在一个 `ViewModelFactories.kt` |
| 未来云同步 | 迁移成本 | Repository 已隔离数据源，新增 RemoteDataSource 即可 |

## 8. 结论
