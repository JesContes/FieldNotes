# 寸笺 · 数据导入导出设计

| 项目 | 内容 |
| --- | --- |
| 目标 | 换机 / 重装时完整迁移分类、物品、模板、计划及清单勾选态 |
| 格式版本 | v1（`format: field-notes-export`） |
| 默认格式 | UTF-8 紧凑 JSON；可选 gzip |
| 实现位置 | `data/transfer/ExportCodec.kt`、`TransferFiles.kt`、`ui/transfer/TransferViewModel.kt` |
| 示例文件 | [samples/export-sample.json](samples/export-sample.json) |
| 实测 | 示例集 **5,357 B**；gzip **1,483 B** |

---

## 1. 设计目标与约束

| 目标 | 说明 |
| --- | --- |
| 完整 | 四类数据 + 模板 / 计划条目 + 勾选态 + 时间戳全部还原 |
| 可引用 | 分类、物品、模板、计划之间的引用关系在导入后仍然正确 |
| 够小 | 键名短、日期用整数、分类用下标；示例集 5.2 KB |
| 可读 | 直接打开能看懂；出问题可人工排查，不依赖专用工具 |
| 免权限 | 使用系统文件选择器（SAF），不申请存储权限 |
| 可演进 | 新增可选字段不破坏旧文件；版本过高明确拒绝 |
| 安全 | 不执行外部内容；限制文件大小、解压后大小与条目数 |

## 2. 格式选型对比

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| A. 全字段 JSON | 最易读，键名自解释 | 键名重复、日期 / 颜色写成字符串，体积最大 | 参考基线 |
| B. **紧凑键 JSON**（选中） | 可读性尚可（配本文档），体积小，无第三方依赖 | 需要文档说明键义 | ✅ 默认 |
| C. CSV | 体积接近 B，可用 Excel 打开 | 模板 / 计划是嵌套结构，需要多文件；逗号 / 换行 / 引号转义易错 | ❌ |
| D. gzip 包装的 JSON | 再省 50%–80% | 不可直接阅读；小文件头开销占比高 | ✅ 可选 |
| E. protobuf / 自定义二进制 | 体积最小、解析快 | 需要 schema，无法人工排查，对本地小数据过度设计 | ❌ |

**结论：默认 B；提供 D（同结构 JSON 的 gzip 包装）。导入端按文件头 `1F 8B` 自动识别，不依赖扩展名。**

## 3. v1 格式规范

### 3.1 顶层结构

```json
{
  "format": "field-notes-export",
  "version": 1,
  "exportedAt": 1792905878,
  "appVersion": "1.0",
  "categories": [],
  "items": [],
  "templates": [],
  "plans": []
}
```

| 键 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `format` | string | ✅ | 固定 `field-notes-export`，识别文件来源 |
| `version` | int | ✅ | 格式版本，当前 `1` |
| `exportedAt` | int | — | 导出时间（Unix 秒） |
| `appVersion` | string | — | 导出时的应用版本，便于排障 |
| `categories` | object[] | ✅ | 分类，数组顺序 = `sortOrder` |
| `items` | object[] | ✅ | 物品 |
| `templates` | object[] | ✅ | 模板（含条目） |
| `plans` | object[] | ✅ | 出行计划（含清单） |

> 空集合必须写 `[]`，不写 `null`；导入端对缺失数组按空处理，但导出端始终写全。

### 3.2 分类 `categories[]`

| 键 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `n` | string | ✅ | 名称，1–12 字 |
| `c` | string | — | 颜色 `#RRGGBB`，缺省 `#66CCFF` |
| `a` | int | — | 创建时间（Unix 秒），缺省导入时刻 |

- **数组下标即 `sortOrder`**，不再单独写 `o`；
- 分类名（归一化后）是导入去重键；
- 「未分类」不导出（它是虚拟分类）。

### 3.3 物品 `items[]`

| 键 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `n` | string | ✅ | 名称，1–40 字，全局唯一 |
| `k` | int \| string | ✅ | 分类：`categories` 下标；也接受直接写分类名（便于手改） |
| `r` | string | — | 备注，≤100 字；为空省略 |
| `a` | int | — | 创建时间（Unix 秒） |
| `u` | int | — | 更新时间（Unix 秒） |

- `k` 为越界下标：物品仍导入，分类置空（未分类），并计入“忽略 1 条分类引用”；
- 物品名（归一化后）是导入去重键；
- 物品没有 `sortOrder`，列表按分类顺序 + 名称排序。

### 3.4 模板 `templates[]`

| 键 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `n` | string | ✅ | 模板名，1–30 字，全局唯一 |
| `d` | string | — | 说明，≤140 字；为空省略 |
| `c` | string | — | 主题色，缺省 `#4DB6AC` |
| `a` | int | — | 创建时间（秒） |
| `u` | int | — | 更新时间（秒） |
| `l` | int | — | 最近使用时间（秒）；从未使用则省略 |
| `it` | object[] | ✅ | 模板条目，数组顺序 = 模板内 `sortOrder` |

模板条目 `it[]`：

| 键 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `n` | string | ✅ | 物品名，1–40 字 |
| `g` | string | — | 分类名快照；空串 / 省略 = 未分类 |

- 条目只存快照，不引用 `items[]` 下标；因此允许条目名在物品库中不存在；
- 同一模板内按 `nameKey` 去重，保留第一条。

### 3.5 计划 `plans[]`

| 键 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `t` | string | — | 计划名称，≤30 字；为空则展示用目的地 |
| `dst` | string | ✅ | 目的地，1–40 字 |
| `s` | int | ✅ | 出发日，**epochDay**（如 `20752` = 2026-10-26） |
| `e` | int | ✅ | 返程日，epochDay，≥ `s` |
| `c` | string | — | 主题色，缺省 `#66CCFF` |
| `m` | string | — | 备注，≤200 字；为空省略 |
| `a` | int | — | 创建时间（秒） |
| `u` | int | — | 更新时间（秒） |
| `it` | object[] | ✅ | 清单条目，数组顺序 = 清单内 `sortOrder` |

清单条目 `it[]`：

| 键 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `n` | string | ✅ | 物品名，1–40 字 |
| `g` | string | — | 分类名快照；省略 = 未分类 |
| `x` | int \| bool | — | 勾选态；`1` / `true` 为已勾选，缺省 `0` / `false` |

- 计划条目按 `nameKey` 去重；
- 勾选态随文件迁移（换机后仍能看到哪些已打包）；
- 计划、模板与所有条目均不导出数据库主键 `id`，导入时重新分配。

### 3.7 空间优化清单

| 手段 | 效果 |
| --- | --- |
| 短键 `n/k/r/a/u/c/g/x/m/dst/s/e/t/l/it` | 键名从 3–12 字符压到 1–4 字符 |
| 日期用 epochDay 整数 | `"2026-10-26"` → `20752`，每条省 5–6 B |
| 时间戳降为秒 | 每条省 3 B |
| 分类用下标 | 物品行省 2–10 B；分类名越长收益越大 |
| 数组顺序表达 sortOrder | 省掉 `o` 字段 |
| 空字段省略（`r/m/d/l/x`） | 常见情况每条省 4–12 B |
| 可选的 gzip | 示例集 5,357 B → 1,483 B |

## 4. 体积实测

测算脚本：[`tools/measure_export_size.py`](../tools/measure_export_size.py)。数据为 6 分类、4 模板（46 条目）、3 计划（25 条目），物品备注与名称取自真实出行场景。

| 数据规模 | 全字段 JSON | 紧凑 JSON | 紧凑 + gzip | 相对全字段 | gzip 相对全字段 |
| --- | --- | --- | --- | --- | --- |
| 26 物品 / 4 模板 / 3 计划 | 8,176 B | **5,357 B** | **1,483 B** | −34.5% | −81.9% |
| 100 物品 / 4 模板 / 3 计划 | 15,665 B | 9,728 B | 2,243 B | −37.9% | −85.7% |
| 200 物品 / 4 模板 / 3 计划 | 25,779 B | 15,623 B | 3,159 B | −39.4% | −87.7% |
| 500 物品 / 4 模板 / 3 计划 | 56,129 B | 33,323 B | 5,732 B | −40.6% | −89.8% |
| 1000 物品 / 4 模板 / 3 计划 | 106,715 B | 62,828 B | 9,908 B | −41.1% | −90.7% |

**解读**

- 单条物品成本约 **55–60 B**（含名称、分类下标、两个时间戳与短备注）；模板 / 计划条目约 **18–25 B/条**（名称 + 分类快照）；
- 示例集仅 **5.2 KB**，远小于一张照片；即使 1000 物品也只有 **61 KB**（明文）/ **9.7 KB**（gzip）；
- gzip 的 82%–91% 收益偏高，因为合成数据的分类名、物品名重复度较高；真实数据建议按 **50%–85%** 预估。经验阈值：明文超过约 **4 KB**（≈60 条物品）时再考虑压缩，小文件 gzip 头开销反而明显；
- 导出文件名：`寸笺-yyyyMMdd-HHmm.json`；压缩版追加 `.gz`。MIME：`application/json` / `application/gzip`。

## 5. 导出流程

```
点击“导出数据（JSON / .gz）”
  → ViewModel.export(gzip)
  → Repository.loadSnapshot()            // 单事务读取六张表
  → ExportCodec.encode(snapshot, gzip)   // UTF-8 紧凑 JSON
  → SAF ACTION_CREATE_DOCUMENT            // 用户选择目录 / 文件名
  → ContentResolver.openOutputStream(uri)
  → 写入 bytes；失败则尝试删除半成品
  → Toast「已导出 5.2 KB」
```

- 快照在**一个事务**内读取，避免导出过程中数据变化导致“分类有、物品没有”；
- 文件在内存中一次性生成（示例集 < 100 KB，1000 物品 < 1 MB），不落临时文件；
- 写文件失败（空间不足 / Uri 失效）：关闭流、尝试删除、Toast 提示；
- 用户取消保存面板：静默返回，不提示错误。

## 6. 导入流程

```
点击“导入数据…”
  → SAF ACTION_OPEN_DOCUMENT
  → 读取 bytes（上限 32 MB）
  → 按文件头识别 gzip（1F 8B）
  → 解压（解压后上限 128 MB，防 zip bomb）
  → UTF-8 解码（容忍 BOM）
  → ExportCodec.decodeAndValidate()
  → 预览统计（分类 / 物品 / 模板 / 计划 / 条目 / 重复 / 无效）
  → 用户选择「合并 / 覆盖 / 取消」
  → Repository.importAll(plan, mode)      // 单事务
  → Flow 刷新全部界面 + Toast 汇总
```

### 6.1 校验与容错

| 检查 | 失败处理 |
| --- | --- |
| `format` 不等于 `field-notes-export` | 整体拒绝：“这不是有效的寸笺导出文件” |
| `version > 1` | 整体拒绝：“文件版本过高，请先升级应用” |
| `version < 1` / 缺失 | 整体拒绝：“文件版本不受支持” |
| JSON 解析失败 | 整体拒绝：“文件内容损坏，无法解析” |
| 文件 > 32 MB / 解压后 > 128 MB | 整体拒绝：“文件过大” |
| 分类数组 > 1000、物品 > 10000、模板 / 计划 > 5000、条目 > 100000 | 整体拒绝：“数据量超出上限” |
| 单个名称超长 | 截断到上限，继续导入 |
| 名称为空 | 跳过该条，计数为无效 |
| 日期越界（1900-01-01 – 2200-12-31）或 `e < s` | 跳过该计划，计数为无效 |
| 颜色不是 `#RRGGBB` | 回退默认色，不失败 |
| `k` 分类下标越界 | 物品分类置空（未分类），继续导入 |
| `x` 非 0/1/true/false | 视为未勾选 |
| 条目重复（同容器 nameKey） | 保留第一条，后续跳过并计入重复 |
| 未知键 | 忽略，向后兼容 |

> 单条脏数据只跳过该条，不拖垮整个文件；结构性错误（格式 / 版本 / JSON）才整体拒绝。

### 6.2 合并（MERGE）

**去重键**

| 对象 | 键 |
| --- | --- |
| 分类 | `nameKey` |
| 物品 | `nameKey`（全局） |
| 模板 | `nameKey` |
| 计划 | `planKey = nameKey(title.ifBlank { destination }) + "|" + nameKey(destination) + "|" + startEpochDay + "|" + endEpochDay` |
| 模板 / 计划条目 | 容器内 `nameKey` |

**算法**

```
开始事务
  读取本机分类 / 物品 / 模板 / 计划的现有键集合
  // 1. 分类
  for 文件分类 in 顺序:
      如果 nameKey 已存在: 复用本机 id
      否则: INSERT，得到新 id
      记录 文件下标 → 本机 id
  // 2. 物品
  for 文件物品 in 顺序:
      如果 nameKey 已存在: 跳过（不更新备注 / 分类）
      否则: 解析 k → 本机分类 id（越界则 null）
            INSERT，得到新 id
  // 3. 模板
  for 文件模板 in 顺序:
      如果 nameKey 已存在: 整个模板跳过（不合并条目）
      否则: INSERT template；逐条 INSERT template_item
  // 4. 计划
  for 文件计划 in 顺序:
      如果 planKey 已存在: 整个计划跳过
      否则: INSERT plan；逐条 INSERT plan_item（含 checked）
  提交事务
返回 插入 / 跳过 / 无效 计数
```

**合并语义（明确写入文档与 UI）**

- 只补充本机没有的对象；**不更新**已有对象的名称、备注、颜色、勾选态；
- 模板 / 计划重复时整对象跳过，不做“条目级合并”，避免半新半旧；
- 需要“完全一致”的恢复，使用覆盖模式；
- 导入文件内部的重复同样保留第一条。

### 6.3 覆盖（REPLACE）

```
开始事务
  DELETE FROM plan_item; DELETE FROM plan; DELETE FROM template_item;
  DELETE FROM template; DELETE FROM item; DELETE FROM category;
  按导出顺序重新插入全部对象（仍按 nameKey 去重，处理文件内重复）
  // 分类 sortOrder = 数组下标
  // 计划 / 模板条目 sortOrder = 数组下标
提交事务
```

- 覆盖前二次确认：“将清空本机 3 个计划、4 个模板、26 件物品，且不可恢复”；
- 覆盖在单事务内完成，失败回滚，**不会出现清空成功但导入失败**；
- 覆盖不重置 DataStore（筛选记忆保留；若筛选目标已不存在，自动回退「全部」）。

### 6.4 主键与引用重建

- 文件**不包含任何数据库 id**；
- 导入时所有对象获得新的自增 id；
- 物品 → 分类：用 `文件 k（分类下标）→ 导入时新建的分类 id` 映射；
- 模板 / 计划条目 → 物品：**不引用**，只保留名称与分类名快照；
- `sourceItemId` 不入文件，导入后为 `null`；
- 因此导入不会产生“指向不存在记录”的外键，也不需要按 id 对齐。

### 6.5 勾选态

- `x = 1` / `true` → `checked = true`；缺省 → false；
- 勾选态只影响 `plan_item`，模板条目没有勾选态；
- 合并模式下，已存在计划的勾选态保持本机值，不被文件覆盖；
- 覆盖模式下，勾选态完全按文件恢复。

## 7. 安全与隐私

- **无网络**：应用不声明 `INTERNET` 权限，导入导出完全本地；
- **无存储权限**：只通过 SAF 读写用户选择的 Uri，不扫描外部存储；
- **不执行外部内容**：`org.json` 只做数据解析，不反射、不加载类、不执行脚本；
- **大小限制**：文件 32 MB、解压后 128 MB、条目数上限，防内存耗尽与 zip bomb；
- **类型校验**：所有字段按类型读取，非法类型走默认值或跳过；
- **无临时文件**：编解码在内存完成，不把用户数据写到缓存目录；
- **备份策略**：`allowBackup="false"`，避免系统云备份绕过用户意图；
- **导出文件**由用户自行保管，应用不上传、不统计、不记录路径。

## 9. 版本演进规则

| 变更 | `version` | 读取端策略 |
| --- | --- | --- |
| 新增可选字段 | 不变 | 旧版本忽略未知键；新版本缺省值兜底 |
| 修改字段含义 / 必填性 | +1 | 按版本分支解析；旧字段保留兼容读取 |
| 删除字段 | +1 | 至少保留一个大版本的兼容读取 |
| 数组结构变化 | +1 | 旧版本拒绝，提示升级 |
| 文件 `version` 高于当前支持 | — | 一律拒绝，绝不“猜着读” |

## 10. 测试矩阵

| 用例 | 输入 | 期望 |
| --- | --- | --- |
| 导出往返 | 26 物品 / 4 模板 / 3 计划 | JSON → 导入 → 数据、勾选态、时间戳一致 |
| gzip 往返 | 同上，导出 .gz | 文件头 `1F 8B`；导入后与明文一致 |
| 合并去重 | 同一文件导入两次 | 第二次全部跳过，数量不变 |
| 覆盖恢复 | 清空后导入 | 四类数据完全恢复；筛选回退全部 |
| 文件内重复 | 两个同名物品 / 模板条目 | 保留第一条，计数为重复 |
| 分类下标越界 | `k = 99` | 物品导入为未分类，不崩溃 |
| 脏日期 | `s = 999999` | 跳过计划，其他数据正常 |
| 超长名称 | 100 字物品名 | 截断 40 字后导入 |
| 非法颜色 | `c = "blue"` | 回退默认色 |
| 版本过高 | `version = 2` | 整体拒绝 + 明确提示 |
| 格式不符 | 任意 JSON | 整体拒绝 + 明确提示 |
| 损坏文件 | 截断的 JSON | 整体拒绝，不写库 |
| 空文件 / 0 字节 | — | 提示“文件为空” |
| 超大文件 | > 32 MB | 拒绝，不读取 |
| 取消 SAF | — | 无副作用，无错误提示 |
| 导入中断 | 导入中杀进程 | 事务回滚，原数据完整 |
| 导出中断 | 写入中拔存储 / 空间不足 | 提示失败；本机数据不受影响 |
| 勾选态迁移 | 7 条中 2 条勾选 | 导入后仍为 2 条勾选，红点状态一致 |
| 计划四元组重复 | 同名同目的地同日期 | 合并跳过；覆盖恢复 |

## 11. 结论

v1 采用**紧凑 JSON + 可选 gzip + SAF + 单事务合并 / 覆盖**：

- 示例集仅 5.2 KB，1000 物品约 61 KB，迁移成本可忽略；
- 四类数据与勾选态完整往返，引用通过名称与下标重建，不依赖数据库 id；
- 合并只补缺、覆盖先清空，语义清晰，避免“半合并”；
- 所有限制与容错在文档中明确，导入导出可单测、可人工排查。
